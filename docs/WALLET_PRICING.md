# 천년지기 충전식 포인트 정책 (구현 단계)

- 1포인트 = 1원
- AI 상담 답변 1건 **성공적으로 저장 시** 100포인트 사용
- 포인트 부족 시 상담 요청 거절, 잔액 음수 불가
- 상담 처리 실패 시 같은 요청에 대한 환급 원장 기록
- 충전 승인된 주문만 서버에서 1회 적립; 중복 적립 방지
- 실제 결제와 포인트 사용은 기본 비활성화

## SQL 적용 순서
1. `supabase/payment_orders.sql`
2. `supabase/wallet.sql`

## 환경 변수
- `WALLET_CHARGING_ENABLED=true`: 상담 100P 차감 활성화. **실서비스에 켜기 전에 결제·복구 테스트 필수**
- `TOSS_TEST_PAYMENTS_ENABLED=true`: 토스 테스트 승인 기능. 테스트 시크릿 키만 허용.
- `TOSS_SECRET_KEY`: 서버 전용으로 재발급한 `test_gsk_` 키.

## 남은 작업
- 고객이 선택할 충전 금액(예: 1천원, 3천원 등)과 환불 정책 확정
- 서버에서 금액을 확정하는 주문 생성 API 및 토스 SDK 결제창
- 승인 후 원장 적립 실패/타임아웃 복구용 관리자 재처리
- 포인트 차감/상담 저장을 하나의 DB 트랜잭션으로 묶는 강화 작업
- 기존 하루 무료 3회 제한을 유료 정책에 맞게 전환
- 결제 취소·부분 취소 시 포인트 회수 및 부족 잔액 처리 정책
- DB 적용, CI 통과, 결제 테스트, 배포 검증

**주의**: 현재 상담 API의 하루 3회 무료 베타 제한은 유지됩니다. 차감 플래그를 켜면 100P 차감과 기존 일일 제한이 동시에 적용되므로 운영 전 반드시 정책과 코드를 함께 변경해야 합니다. 플래그를 아직 켜지 마세요.
